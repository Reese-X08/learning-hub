## 三、技术架构

```
单个 HTML 文件
├── <style>   全部样式（CSS 变量 + 新拟态/毛玻璃风格）
├── <body>    固定 DOM 骨架（header / sidebar / main / 2 个 modal）
└── <script>  原生 JS，无框架、无依赖
      ├── state          内存中的全局数据对象
      ├── save()         写回 localStorage
      ├── render*()      全量重绘（数据变更后统一调用）
      └── 事件处理        全部用 onclick 内联绑定
```

技术特征：

- 无 npm、无打包、无 CDN 依赖 → 完全离线可用
- 渲染方式：字符串拼接 `innerHTML` 全量重绘，无虚拟 DOM
- 路由：无，单页面内切换视图
- 状态管理：单一 `state` 对象 + 手动 `save()`

## 四、数据结构（核心）

### 4.1 存储位置

| 项 | 值 |
|---|---|
| 存储介质 | `localStorage` |
| Key | `taskApp2` |
| 值格式 | JSON 字符串 |
| 容量上限 | 浏览器约 5MB（含 Base64 文件，实际可用更少） |

### 4.2 顶层结构

```json
{
  "categories": [ /* 分类数组 */ ],
  "tasks": [ /* 任务数组 */ ]
}
```

### 4.3 分类对象 Category

```json
{
  "id": "hw",
  "name": "家庭作业",
  "color": "#3b82f6"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识。默认分类用短 id，新建分类用 `'c' + Date.now()` |
| `name` | string | ✅ | 分类显示名 |
| `color` | string | ✅ | 十六进制色值，用于圆点、任务卡背景与文字 |

**默认三个分类**（首次打开时自动写入）：

| id | name | color |
|---|---|---|
| `hw` | 家庭作业 | `#3b82f6` |
| `sch` | 日程安排 | `#22c55e` |
| `per` | 个人事务 | `#f59e0b` |

### 4.4 任务对象 Task

```json
{
  "id": "1728547200000",
  "title": "完成数学作业",
  "date": "2026-10-27",
  "cat": "hw",
  "note": "第三章 1-10 题",
  "priority": 2,
  "done": false,
  "files": [
    {
      "name": "作业要求.pdf",
      "size": 183420,
      "type": "application/pdf",
      "data": "data:application/pdf;base64,JVBERi0xLjQK..."
    }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识，创建时用 `Date.now().toString()` |
| `title` | string | ✅ | 任务标题（空标题不允许保存） |
| `date` | string | ✅ | 日期，严格 `YYYY-MM-DD` 格式 |
| `cat` | string | ✅ | 所属分类 id，需存在于 `categories` |
| `note` | string | ❌ | 备注，可为空字符串 |
| `priority` | number | ✅ | 优先级：`1`=低 / `2`=中 / `3`=高 |
| `done` | boolean | ✅ | 是否完成 |
| `files` | array | ❌ | 相关文件列表，旧数据可能没有此字段（代码已兼容） |

### 4.5 文件对象 File

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 原始文件名（含扩展名） |
| `size` | number | 字节数 |
| `type` | string | MIME 类型，如 `image/png` |
| `data` | string | **Base64 Data URL**，格式 `data:{mime};base64,{content}`，可直接赋给 `<a href>` 下载 |

约束：

- 单文件上限 **2MB**（`MAX_FILE_SIZE = 2 * 1024 * 1024`），超出会被拦截并 alert
- 无文件类型白名单，任意类型可上传
- 文件内容随任务一起存进 localStorage，**会显著占用配额**

## 七、与其他程序整合方案

### 方案 A：数据层直连（最快，零改造）

其他程序（同源页面 / 浏览器扩展 / Electron 主进程）直接读写 localStorage：

```js
// 读
const data = JSON.parse(localStorage.getItem('taskApp2') || '{}');

// 写（务必保持结构完整）
localStorage.setItem('taskApp2', JSON.stringify(data));
// 然后刷新页面或调用 render()
```

适用：浏览器扩展、同源 Web 工具、Electron/Tauri 桌面壳。
限制：跨域、跨设备、跨浏览器全部不通。

### 方案 B：增加 JSON 导入/导出（推荐先做）

在页面加两个按钮：

```js
// 导出
function exportData() {
  const blob = new Blob([JSON.stringify(state, null, 2)], {type: 'application/json'});
  const a = document.createElement('a');
  a.href = URL.createObjectURL(blob);
  a.download = `tasks-${new Date().toISOString().slice(0,10)}.json`;
  a.click();
}

// 导入
function importData(json) {
  const d = JSON.parse(json);
  if (!Array.isArray(d.tasks) || !Array.isArray(d.categories)) throw new Error('格式不正确');
  state = d;
  save(); render();
}
```

适用：需要和任意其他程序交换数据，且不想改架构。
这也是本项目当前**最应该补的一环**。

### 方案 C：抽离数据层 + 后端 API

把 `save()/load()` 换成异步请求：

```js
async function load() { state = await fetch('/api/state').then(r => r.json()); }
async function save() { await fetch('/api/state', {method:'PUT', body: JSON.stringify(state)}); }
```

需要同步改造的点：

1. 所有 `save()` 调用改为 `await`，或加防抖队列
2. 文件不再存 Base64，改为 `POST /api/files` 上传后只存 `{id, name, size, url}`
3. 增加冲突处理（多端同时改）

适用：多设备同步、多人协作、要接其他系统。

### 方案 D：工程化重构

拆成 Vue/React + Vite 工程，`state` 换成 Pinia/Zustand，文件上传走对象存储。

适用：后续功能会持续膨胀、需要组件复用与测试。
代价：失去「双击即用」的零依赖优势。

## 八、整合注意事项（必读）

1. **`file://` 协议下 localStorage 行为不一致**
   Chrome 对本地文件按路径隔离存储，Firefox 则所有本地文件共享。若你用桌面快捷方式打开（`file://`），换路径或换浏览器可能读不到原数据。
   → 整合前建议先做一次 JSON 导出备份；或改用本地 HTTP 服务打开（`http://localhost`）。

2. **文件是 Base64 内嵌的**
   导出 JSON 时文件内容会一起导出，体积可能是原文件的 1.33 倍。大文件场景必须改方案 C。

3. **`id` 用时间戳生成**
   `Date.now().toString()` 在极短时间内连续创建有碰撞风险。若其他程序要批量写入，建议改用 UUID。

4. **删除不可恢复**
   `deleteTask` 直接过滤数组，无回收站、无撤销。整合时若要支持恢复，需自行加软删除字段。

5. **分类删除功能不存在**
   当前只能新增分类，不能删改。若其他程序需要管理分类，需自行补 CRUD。

6. **没有用户/权限概念**
   单用户单浏览器。多人场景必须上后端。
