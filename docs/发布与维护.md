# 发布与维护

> 面向维护者：怎么打新版本、怎么让使用者拿到更新。
> 使用者请看 [使用指南](使用指南.md)。

## 一、更新与分发

### 给同学发新版

改完代码后重新打 zip 发出去即可。**更新包不含 `data/`，覆盖解压不会冲掉使用者的课程和任务。**

使用者那边只有三步：

1. 下载新 zip
2. 解压到旧的「学习中心」文件夹上，选「替换目标中的文件」
3. 关掉旧窗口，双击 `启动.bat`

`data/db.json` 不在包里，所以解压时不会被覆盖。第一次启动时 `启动.bat` 会从 `data/db.template.json` 生成一份空白数据。

### 版本号

- `package.json` 里的 `version` 就是版本号（当前 `2.9.0`）
- 界面上：**⋯ → 检查更新** 能看到当前版本；**站点设置** 左下角也显示「版本 2.9.0」
- 服务端：`GET /api/version` 返回 `{ "version": "2.9.0" }`

发版时先改 `package.json` 的版本号，再重新打包，使用者就能在站点设置里确认拿到的是不是新版。

### 怎么让使用者知道有新版本

程序自己带着本地服务端，所以可以做到**应用内推送**，不用用户反复点「检查更新」：

1. **服务端定时检查**（默认开启，不需要任何设置）
   - 启动约 2 秒后查一次，之后每 30 分钟查一次；窗口关掉、服务还在后台跑时也照查
   - 默认同时问 4 条线路：GitHub raw、jsDelivr、jsDelivr Fastly、GitHub Releases API
   - 站点设置里的「更新检查地址」优先；自定义地址不通时自动回退到官方线路
   - 检查结果写到 `data/update-state.json`，重启后能立刻恢复上次查到的版本
2. **SSE 实时推送**
   - 页面登录后打开 `/api/events` 长连接；服务端一查到新版本，就推给所有打开的窗口
   - 界面表现：顶部提示条、菜单 `⋯` 上的小红点、页面 toast 同时出现
   - 想要窗口最小化也收到提醒，可在「检查更新」里勾选「发现新版本时弹系统通知」（浏览器会问一次权限）
   - EventSource 断线会自动重连；另有 5 分钟轮询兜底，切回窗口时也会补查
3. **应用内一键更新**（2.6.0 起）
   - 弹窗里的「立即更新」会读取 `version.json` 旁边的 `update-manifest.json`
   - 只下载和本地 SHA-256 不同的文件（通常几百 KB），不碰 `node/` 和 `data/`
   - 每个文件校验大小和哈希，JS 会先跑 `node --check`；替换前备份到 `data/update-backup/<version>/`
   - 替换完由 `lib/restart-helper.js` 重启服务并轮询 `/api/version`；新版本起不来会自动恢复上一版
   - 没有清单、清单版本对不上、校验失败时，界面会提示并保留「下载更新器」的退路
4. **独立自动更新器**（2.10.0 起，所有旧版本适用）
   - `updater.ps1` + `更新.bat` 打包成约 20KB 的 `learning-hub-updater.zip`
   - 双击 `更新.bat` 后：读取 `version.json` → 下载 `codeUrl` 代码包 → 停旧服务 → 备份/替换 → 启动并轮询 `/api/version`
   - 不依赖当前版本里有没有自更新代码，所以 2.5.1 / 2.6.x / 2.9.x 都能直接用它
   - 新版本启动失败会自动恢复上一版并重新启动旧服务
   - 页面会检测服务端版本变化并自动刷新；标题旁显示 `v版本号`
5. **发版要做的**
   - 改 `package.json` 的 `version`、`version.json` 的 `notes`
   - 打 tag 推送；CI 会把 tag 版本写进这两个文件、运行 `node tools/build-update-manifest.js` 生成清单，再打包三个 zip
   - 确认 `main` 分支上的 `version.json` / `update-manifest.json` 已经是新版本（CI 会自动回写；失败就手动提交一次）
6. **群公告 / 群文件**：仍然是最省事的补充，改完在群里说一句。

`version.json` 现在带两个下载地址：

```json
{
  "version": "2.10.0",
  "notes": "这次更新了什么",
  "url": "https://github.com/<你>/<仓库>/releases/latest/download/learning-hub-updater.zip",
  "codeUrl": "https://github.com/<你>/<仓库>/releases/latest/download/learning-hub-code.zip"
}
```

- `url`：旧版本「去下载」/ 应用内「下载更新器」用，指向自动更新器
- `codeUrl`：更新器实际下载的代码包；没填时更新器会退回用 `url`，再不行用固定的 `learning-hub-code.zip`

自更新清单只包含运行时会用到的文件：`server.js`、`package.json`、`version.json`、`updater.ps1`、`lib/*.js`、`public/*`。
`public/code-lab.js` / `public/code-lab.css` 是代码学习台的静态文件，会自动进清单。
`lib/restart-helper.js` 故意不在清单里，避免一次坏更新把重启/回滚逻辑本身换掉。
`启动.bat` 也不在清单里（批处理文件对换行敏感）；如果改了启动脚本，需要发一次代码更新包或完整包。

> **旧版本升级不再需要手动覆盖**：2.10.0 起提供独立更新器。
> 2.5.1 / 2.6.x / 2.9.x 用户下载 `learning-hub-updater.zip`（约 20KB），
> 解压后双击 `更新.bat`，按提示选择学习中心文件夹即可。
> 更新器会自动下载代码包、停服务、备份/替换、启动并验证版本号。
> 2.7.0 / 2.8.0 / 2.9.0 的改动也都包含在代码包里，不需要逐版本手动复制。

排查更新检查：

- 菜单 **⋯ → 检查更新** 会显示当前版本、最新版本、来源和错误信息
- `data/update-backup/` 是上一版文件备份；`data/update-error.json` 记录最近一次失败原因；`data/update-restart.log` 是重启助手的日志
- `data/update-state.json` 是最近一次成功检查的结果；删掉它只会让界面回到「还没检查过」
- 校园网 / 公司网挡住 GitHub 时会自动走 jsDelivr；全都不通时只提示「暂时连不上更新服务」，不影响课程和事务
- 想改检查频率，可给 `createUpdateChecker` 传 `intervalMs`（默认 30 分钟），或后续在站点设置里加选项

### 为什么 GitHub 上的软件不弹「Windows 已保护你的电脑」

其实**它们也会弹**，只是大项目用三招绕开了：

| 手段 | 说明 |
| --- | --- |
| **代码签名证书** | SmartScreen 的信誉绑在证书上。签名过的安装包，即使没人下载过也很少拦（EV 证书可立即获得信誉） |
| **安装包而非脚本** | 主流项目发的是 `.exe` / `.msi` 安装程序，签名 + 打包，比 `.bat` 触发拦截的概率低得多 |
| **下载量积累信誉** | SmartScreen 是按"这个文件有多少人下过且没被举报"算信誉的，冷门新文件必然被拦一次 |

还有两个容易忽略的点：

- **Mark of the Web**：从浏览器下载的文件会被打上"来自其他计算机"标记，解压后依然带着。所以 GitHub 的 zip 也会触发提示。
- **Smart App Control**（Win11 22H2+）：对未签名程序直接拒绝运行，比 SmartScreen 更狠。GitHub 上的小项目在开了 SAC 的机器上一样跑不起来。

我们是"`.bat` + 未签名自带的 node.exe"，属于最容易被拦的组合。实际上没有廉价解法（给 `.bat` 签名没用，给 node.exe 签名要买证书）。

**务实的做法**：在说明里写清楚一次性解除方法（已加进 `使用说明.txt`）：

> 右键 zip → 属性 → 勾选「解除锁定」→ 确定，再解压；运行时若提示，点「更多信息 → 仍要运行」。

### 扩展怎么更新

浏览器扩展（unpacked 方式加载的）**不会自动更新**，也不支持静默升级。更新步骤：

1. 用新的 `extension/` 文件夹覆盖旧的
2. 打开 `edge://extensions`，点扩展卡片上的「重新加载」
3. 如果提示权限有变化（比如匹配范围变了），点「允许」

扩展自己也有版本号（`extension/manifest.json` 的 `version`，当前 `1.1.1`），在 `edge://extensions` 的卡片上能看到。

> 想让它自动更新，只能上架 Edge 加载项商店（免费，但要审核），或者用企业策略分发。对个人/班级使用来说，重新加载更省事。

## 二、开源到 GitHub

### 仓库里放什么

源码（`server.js`、`lib/`、`public/`、`extension/`）+ 打包模板（`templates/`）+ 构建脚本（`tools/`）+ 自更新清单（`update-manifest.json`）+ CI 配置。**不放**：`data/`（个人数据）、`dist/`、`*.zip`（体积）、`node/`（运行时，构建时下载）。

### 第一次上传

```bash
git init
git add .
git commit -m "初始提交"
git branch -M main
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

推送前确认 `git status` 里**没有** `data/` 和 `学习中心-便携版.zip`——`.gitignore` 已经挡住了。

### 发一个版本

```bash
# 1. 改 package.json 里的 version（比如 2.3.1），顺手更新 version.json 的 notes
git add package.json version.json
git commit -m "发布 v2.3.1"
git push

# 2. 打 tag 并推送 —— CI 会自动打包并发布 Release
git tag v2.3.1
git push --tags
```

GitHub Actions（`.github/workflows/release.yml`）会在 Windows runner 上：

1. 把 tag 的版本号写进 `package.json` / `version.json`
2. 跑 `tools/build-package.ps1`（自动下载 Node 运行时）和 `tools/build-update-package.ps1`
3. 跑 `tools/build-updater-package.ps1` 生成约 20KB 的自动更新器
4. 把 `learning-hub-portable.zip`、`learning-hub-code.zip`、`learning-hub-updater.zip` 作为 Release 附件上传
5. 把版本号提交回仓库

约 3～5 分钟出结果，地址形如 `https://github.com/<你>/<仓库>/releases/latest`。

### 换成你自己的仓库

默认更新源是从 `package.json` 的 `repository` 推出来的（GitHub raw / jsDelivr / Releases API）。
把 `package.json` 的 `repository` 和 `version.json` 的 `url` 换成你的地址，重启后就会去你的仓库检查。
自更新会找 `version.json` 同目录的 `update-manifest.json`；`npm run manifest` 生成，发版时 CI 也会跑。

站点设置里的「更新检查地址」只是额外的覆盖项：填了就先查它，不通再回退官方线路；
下载按钮的地址仍然来自 `version.json` 的 `url`。

> 手动发布也可以：本地跑 `tools\build-package.ps1`、`tools\build-update-package.ps1`、
> `tools\build-updater-package.ps1`，把三个 zip 分别改名为 `learning-hub-portable.zip` /
> `learning-hub-code.zip` / `learning-hub-updater.zip` 再拖到 Release 里
> （GitHub 会过滤中文附件名，不改名的话 `version.json` 里的固定下载地址会 404）。

### 仓库地址要写在哪

`package.json` 的 `repository` 和 `version.json` 的 `url` 里都有占位符，换成你自己的即可。
